### 1.2 后端 · 在线充值全链路（支付预留在小程序端跑通）

```
小程序选方案 → 创建待支付充值单（赠送额/送分/赠券随订单固化）
            → 统一下单（Mock 渠道返回 payParams）
            → 用户确认 → mock-success 接口
            → 构造与真实渠道相同的回调报文 + 签名头
            → 验签 → 幂等判断 → 支付单已支付 → 订单已支付
            → AccountService.recharge 入账（复用收银员手工充值的同一逻辑）
            → 补写支付明细 → 赠送积分 → 赠券 → account_credited=1
```

> 赠券配置在下单时以 `[GIFT_COUPONS:2:1,1:1]` 形式固化进订单备注，回调入账时解析，
> 避免方案在支付期间被改动导致赠送不一致（**不用改表结构**）。

## 4. 环境与工具经验（重要，避免重复踩坑）

### 4.1 PowerShell 5.1 的 UTF-8 陷阱（本轮最大的时间消耗点）

本机默认 `powershell.exe` 是 **5.1**，它按 **GBK** 读取无 BOM 的 `.ps1` / `.sql` / `.json` 文件。
只要文件里有中文，就会出现以下**看似无关**的故障：

| 现象 | 真实原因 |
|---|---|
| `Could not find a part of a path`、语法错误指向无关行 | 中文字符被按 GBK 解码成非法字节序列，破坏字符串/括号配对 |
| `package.json` 损坏、`vite: not found` | `Set-Content` 用 GBK 回写，JSON 里的中文 description 破坏结构 |
| SQL 文件出现 `涓婚敭`（"主键"） | PowerShell `-replace` 读写 SQL 时把 UTF-8 当 GBK 处理 |
| `$home` 赋值报 `Cannot overwrite variable HOME` | `$HOME` 是 PowerShell 只读内置变量 |

**规避规则（本项目已落地）**：

1. **所有文本文件处理一律用 Node 脚本**，不要用 PowerShell 的 `-replace`/`Set-Content`/`Out-File` 改含中文的文件；
2. 需要在 PS 5.1 执行的脚本：**保持纯 ASCII**，或写入 **UTF-8 with BOM**；
3. 变量名避开 `$home` / `$host` / `$input` / `$error` 等内置变量；
4. 已提供工具脚本：
   - `scripts/normalize-sql.js` —— SQL 校验与修复（含乱码检测）
   - `scripts/inspect-sql.js` —— DDL 完整性检查（表数/重复/BOM/种子数据/列值数一致性）
   - `scripts/make-test-ascii.js` —— 把测试脚本转为纯 ASCII + BOM

### 4.2 npm 的 `NODE_ENV` 陷阱

本机环境变量 `NODE_ENV=production`，导致 `npm install` **跳过 devDependencies**，
表现为 `vite: not recognized`、`uni build` 找不到命令。

**解决**：`npm install --include=dev`，或安装前 `$env:NODE_ENV="development"`。
